### 4.6 **明确裁定（行业侧命题 4）**【推断·高 / 判断·高】

**判据**：「若任一合理口径变体使触发次数 >0 或余量 <0.5pp，则 v1.5『休眠条款、按构造不触发』应改写为『边界敏感、非结构性免疫』」。

**裁定：判据明确成立，且远超阈值。**

1. **触发次数 >0**：即使只取「核心合理变体」（季度 63 日、v1.5 执行频率），R=15/20/25% 三档分别有 **20 / 22 / 8** 个变体触发；单变量层面，**现金利率 -1pp、全期 1.3% 前瞻压力（v1.5 自用口径）、股息不计入（行业侧简化口径）三项各自独立**使 R=20% 触发 1 次（首次 2016-01-28）。再平衡日历换成日历季末，同一份价格序列下 R=20% 同样触发（2016-01-26）。
2. **余量 <0.5pp**：**v1.5 主口径本身**四档中 R=15%（0.272pp）、R=20%（0.309pp）已 <0.5pp，含税口径 0.270 / 0.485pp，每日再平衡 0.052~0.215pp；160 变体中 R=20% 有 116 个余量 <0.5pp。
3. **结论**：**v1.5「按构造不会触发、休眠条款、不构成尾部保护」的定性不成立为「结构性免疫」，应改写为「边界敏感、非结构性免疫」**——它只是在**某一组特定口径假设**下恰好不触发，而这组假设中任何一项（权重、现金利率、成本、T+1、再平衡日历、股息处理）的合理变动都可能使它触发。**v1.6 不宜再把它当作「永不触发所以无需处理」**，须作为「口径依赖的边界条款」进入 Phase 4 的候选设计与 Phase 5 的状态机检验。
4. **唯一的例外**【事实·高】：R=30%/E=55% 档在全部 160 变体下均不触发（最小余量 +2.189pp），余量结构性较厚。但它是四档中敞口最高档，且 v1.5 §2.2 明确「不建议为收益抬高 R」，故**不改变整体定性**。
5. **不越权声明**：本裁定只针对「按构造不触发」这一**事实性断言**，**不构成第 5 条存废结论**（Phase 4/6）；也不改变第 2 条 75/25 与第 4 条「不做择时」两条不可动摇边界。

## 七、回测引擎改造规格（Phase 5 必须按此实现，本阶段不跑）

**建议新脚本名**：`E:/Desktop/investment/bt_r_clause.js`；输出 `r_clause_data.json`。**基线要求**：`mix/met` 仍逐行复用 `bt_final.js:9-86`；**V0 对照基线**（不减半）必须与 `mix(B.P_MAIN_OPT, {eq})` **逐位对齐并校验通过**后方可跑其余路径。数据集与假设（§一、§二）在迭代轮次中**保持不变**，只更换策略卡输入。

### 7.1 输入参数

沿用 `mix` 全部参数（`eq / w / rebal / interval / cashRate / dyH / dyD / tradeFee / slippage / divTax / execLag / S / E`），**新增** `rClause` 对象：

| 参数 | 类型 / 默认 | 含义 |
| :--- | :--- | :--- |
| `rClause.enabled` | bool / `false` | `false` = 不减半（V0 对照基线） |
| `rClause.R` | number / `0.20` | 账户回撤触发线（四档 15/20/25/30% 全检） |
| `rClause.eqBase` | number / = `eq` | 由 R→E 表查得的初始目标敞口 E |
| `rClause.cutRatio` | number / `0.5` | 触发后目标敞口 = `eqBase × cutRatio`（第 5 条「减半一次」） |
| `rClause.lockDays` | int / `20` | 至少 20 个交易日不恢复 |
| `rClause.recoverMode` | enum `'none'｜'quarterly'｜'review'` / `'review'` | 三条对照路径（见 7.6） |
| `rClause.reviewLagDays` | int 或 `Infinity` / `20` | 书面复核完成到恢复的固定延迟（见 7.4） |
| `rClause.ddBasis` | enum / `'highWaterV'` | **固定为历史净资产高水位 V**（份额法，V 不因任何操作重置），禁止用周期高点 |

### 7.2 状态变量

```js
state = {
  V: 1,                // 历史净资产高水位（份额法），不因减半/恢复/再平衡重置
  eqTarget: eqBase,    // 当前目标敞口（触发后 = eqBase*cutRatio，恢复后 = eqBase）
  cutDone: false,      // 是否已执行过「减半一次」
  triggerIdx: -1,      // 首次触发日索引
  lockUntilIdx: -1,    // = triggerIdx + lockDays
  recovered: false, recoverIdx: -1,
  pendingCut: false,   // T+1 待执行减半
  pendingRecover: false,
  pendingRebal: false, // 沿用 bt_final.js 的 T+1 再平衡挂单
  uH, uD, cash         // 两资产份额与现金（沿用 mix）
}
```

### 7.3 逐日判定顺序（**严格按此顺序，防止前视偏差**）

```
for i in [S..E]：
  1) 用【当日收盘价】按前一日持仓计算当日 nav[i]（含当日涨跌、股息、现金计息、管理费）——与 mix 一致
  2) V = max(V, nav[i])；dd = 1 - nav[i] / V
  3) 【触发判定】若 enabled && !cutDone && dd >= R：
       cutDone = true; triggerIdx = i; eqTarget = eqBase*cutRatio;
       lockUntilIdx = i + lockDays; pendingCut = true（挂 T+1，不在当日成交）
       记 event {type:'trigger', idx:i, date, dd, V, nav}
  4) 【执行 T+1 挂单】按【当日】收盘价成交（即昨日信号今日成交）：
       pendingCut → 按 eqTarget 卖出、计成本；pendingRecover → 按 eqBase 买回、计成本；
       pendingRebal → 按 eqTarget 与 75/25 重置、计成本
  5) 【恢复判定】若 cutDone && !recovered && i >= lockUntilIdx：按 recoverMode 处理（见 7.4/7.6）
  6) 【季度再平衡判定】若 (i-S) % quarterEndIndices(mode) 命中：
       挂 pendingRebal（execLag=1）或当日执行；目标敞口 = 【当前 eqTarget】（见 7.5）
  7) 记录当日快照：{nav, dd, V, eqTarget, eqActual, wInner, cutDone, state...}
```

**前视偏差检查清单（Phase 5 开工前逐项打勾）**：① 触发判定只用**当日收盘后可知**的 `nav[i]`；② 一切成交用**次日收盘价**（`execLag=1`）；③ V 不因任何操作重置；④ 触发日**当日不成交**（`pendingCut` 次日执行）；⑤ 书面复核延迟用**固定参数**，不得引入任何未来信号或人工「看图决策」；⑥ 恢复后不得因 `cutDone=true` 而永久锁死——`cutOnce` 语义是「减半动作只发生一次」，恢复是另一个动作，须分别记事件。

### 7.4 20 日锁定与「书面复核后恢复」的建模方式【判断·中，建模假设，非策略规则】

- 「至少 20 个交易日内不恢复」→ `lockDays = 20`，`i >= triggerIdx + 20` 之前**禁止任何恢复动作**。
- 「到期**不自动恢复**，需书面复核后才能调整」→ 书面复核是**人工动作，回测无法模拟人工判断**。本规格建模为**可参数化的固定恢复延迟**：
  - 基准 `reviewLagDays = 20`（复核在到期当日完成，恢复日 = `triggerIdx + 20`）：标注为**最有利于条款的乐观下界**；
  - 敏感性 `reviewLagDays ∈ {20, 40, 60, Infinity}`，对应行业侧 §3.3 的 40 日机会成本 1.37~5.47pp 区间；`Infinity` 等价于 `recoverMode='none'`（永不恢复）；
  - **复核结论本身不做任何择时判断**（不读估值/宏观/资金流），只按固定延迟恢复，避免把「书面复核」变成隐性择时、违反第 4 条铁律。
- 恢复动作：`eqTarget` 回到 `eqBase`，并在恢复日按 **75/25 重置份额**（一次买入成交，计 T+1 + 成本）；记 event `{type:'recover', ...}`。
- **须在 Phase 5 报告中显式披露**：「书面复核延迟为主观参数假设，非历史事实；其取值会显著影响机会成本，已做 20/40/60/∞ 敏感性」。

### 7.5 **与季度再平衡的冲突处理（宏观侧指出的未定义项，必须明确）**【判断·中，建模假设】

宏观成员 §5.1 指出：「减半后若遇季度末再平衡（第 3 条须按 75/25 重置份额），目标敞口是 E 还是 E/2 未定义」。本规格给出**唯一自洽解**：

> **减半生效期间，季度再平衡的目标敞口 = 当前 `eqTarget`（即 E/2），权益内仍按 75/25 重置份额；季度再平衡不得把 `eqTarget` 拉回 E。只有「恢复动作」才把 `eqTarget` 改回 `eqBase`。**

理由：第 3 条再平衡的职责是「把**实际**比例重置到**当前目标**」，它不改变目标本身；第 5 条已经把目标改为 E/2。若季度末自动拉回 E，等于让第 3 条**架空**第 5 条（且 recovered 状态未变），逻辑不自洽。

- 权益内 75/25 **始终按 `reset` 重置**（遵守 v1.5 第 3 条「禁止同比例缩放」），减半是**同比例缩放总敞口**、不改变权益内构成——与行业侧 §3.1「减半不引入结构畸变」一致。
- **例外（对照路径 iii）**：`recoverMode='quarterly'` 时，季度再平衡日**兼任恢复动作**，把 `eqTarget` 拉回 `eqBase`（见 7.6）。这条正是行业侧命题 3 的「减半但允许按季度再平衡恢复」对照。
- 该冲突在 v1.5 文档中确实未定义；**本规格给出的是显式建模选择（主观、置信度中），须交 Phase 4/6 裁决确认，不是既有策略规则**。

### 7.6 T+1 成交与成本计入

- 所有因**减半 / 恢复 / 再平衡**产生的交易，信号收盘后产生，按**下一交易日收盘价**成交（沿用 `bt_final.js` 的 `pending` 机制）。
- 交易量 = `|目标市值 - 当前市值|` 之和（两资产分别计算）；成本 = 交易量 × (`tradeFee 5bp + slippage 10bp`)，从 `cash` 扣除（沿用 `mix.doRebal`）。
- 减半卖出**一次**成本 + 恢复买入**一次**成本 + 季度再平衡各自成本；股息、现金计息、`FEE_ANN` 沿用 `mix`。
- 建议同时输出 `turnover / feePaid / taxPaid / rebalCount / cutCount / recoverCount`，供 Phase 5 判定「净效应符号」时核算成本。

2. **可复现**：JSON 是唯一可被脚本逐位读取的原始数据；v1.5 §6 是文档记录值，无对应可复现数据文件。
3. **与 Phase 1 一致**：行业侧 §0 已记录同一差异，并声明「不影响本报告任何区间计算（本报告全部基于同一份文件内部序列）」；本裁定与其保持一致。
4. **差异量级**：+2.43 / -1.06 点，相对点位约 0.06% / 0.02%，不改变任何区间结论，但仍须固定。

**执行**：v1.5 §6 的 4054.28 / 5532.07 **仅作历史记录，不进引擎、不进 v1.6 的「当前状态」表**；若 v1.6 需展示 2026-11-06 收盘，用本地 JSON 值并标注来源与快照日。差异本身作为「取数时点/数据源刷新差异」记入局限【事实·中】。

### 裁定 ②：000922 行业权重多口径 —— **不进回测引擎、仅作研究注释**【判断·高】

**理由**：
1. **与第 5 条检验对象无关**：本轮检验的是「总敞口 E 的触发式减半」，账户净值路径由**两指数价格序列 + 现金利率 + 成本**完全决定；行业权重只影响**权益内构成**，而第 2 条 75/25 是不可动摇边界、权益内不设触发式调整。
2. **数据源纪律**：权重来自多个外部网站，快照日不一（2026-06-30 / 09-08 / 09-30 / 10-26 / 11-05 / 11-07），且银行 22.3~22.9%、煤炭 17.19~23.6% 等多口径**未消除**；混入会违反 §三单一数据源口径，制造无法追溯的数值。
3. **无统一快照**：Phase 1 行业侧 §六已把「000922 行业权重的统一口径」列为「数据待更新」，本阶段不具备固定条件。
4. **不损失信息**：行业侧 §2 的行业集中度、因子同向、穿透后单一行业 ≤2.36% 等结论，作为**研究注释**保留在 v1.6 证据披露中即可（含其「账户层分散且可控、权益内集中且放大」的分层结论），无需进引擎。

**执行**：Phase 5 状态机**不读任何行业权重**；v1.6 文档中须保留行业侧的口径澄清（000922 前三大为银行/煤炭/交通运输，「电力」疑为另一红利指数口径，不写成 000922 主要权重行业）与「25% 不承担尾部保护职能」的研究注释建议。
